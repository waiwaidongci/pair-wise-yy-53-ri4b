# 影视内容发行权窗口与独占冲突审阅平台

源提示词编号：10。维护作品、权利类型、地区、语言、窗口、独占和次级授权，联动时间轴与地区矩阵，检测重叠、交叉、倒挂和独占冲突，支持批量调窗、版本差异、评论锚点、审批和追溯导出。

## 双端可续作草稿（法务 × 海外发行）

授权窗口、审阅意见、版本记录已接成**带修订号的服务端权威草稿**，解决两端同时修订互相覆盖的问题：

- **打开带修订号**：`draft` 查询返回完整快照（含 `revision`），未拿到完整快照前只显示加载骨架，不展示半份状态。
- **字段级提交**：每次提交只带“自己改过的字段”和打开时的 `baseRevision`，逐字段记录来源（谁、在哪个修订号写入）。
- **并发保留双来源**：同一窗口两边都改过（对端在本修订号之后保存过同窗口字段），后到补丁**不覆盖**权威稿，作为第二条来源保留，窗口自动退回审阅；**独占标记永不被覆盖**。审阅人在「待定来源」面板逐条采纳/拒绝。
- **冲突结论重算**：冲突使用稳定 key，地区或起止日期一变，消失的旧结论失效；绑定该结论的未处理意见转为「已随变更失效」并保留完整轨迹，待处理意见数与审批门禁同步更新。改独占/优先级等非排期字段不会误使意见失效。
- **版本审批门禁**：高危冲突、待处理意见、退回审阅窗口、待定来源任一存在即关闭；全部清除后可审批锁定，锁定后再有改动审批自动失效。
- **写入失败按原操作号重试**：每个写操作带幂等 `opId`；失败（含顶栏「模拟写入失败」）时草稿不变，操作连同原始入参进入 outbox（本地持久化），可按原 `opId` 续作，服务端幂等回放不重复落库。
- **旧稿迁移**：缺修订号的旧结构在服务端启动时自动迁移到 r1，字段带来源「旧稿迁移」，独占标记原样保留，历史意见按锚点关键词回溯绑定冲突结论，全部仍可追溯。

### 关键模块

| 文件 | 职责 |
| --- | --- |
| `lib/draft/types.ts` | 权威草稿领域模型（修订号、字段来源、并列来源、意见轨迹、冲突结论、门禁、操作日志） |
| `lib/draft/migrate.ts` | 旧稿迁移与意见回溯绑定 |
| `lib/draft/conflicts.ts` | 稳定冲突 key、结论重算与失效判定 |
| `lib/draft/engine.ts` | 纯函数核心：字段级提交、并发保留、意见失效、来源裁决、门禁、幂等 |
| `server/draft-store.ts` | 服务端权威存储（进程内演示存储 + 失败注入） |
| `server/router.ts` | tRPC：`draft` / `submitWindow` / `resolveSource` / `addComment` / `resolveComment` / `approve` |
| `store/ui.ts` | 客户端仅存身份与失败操作 outbox；`runMutation` 统一幂等与失败续作 |
| `trpc/use-draft-actions.ts` | 双端写操作封装与 outbox 重放 |
| `components/PendingSourcesPanel.tsx` | 双来源并列展示与采纳/拒绝 |
| `components/OutboxBanner.tsx` | 写入失败续作条（原操作号重试） |
| `components/Revision.tsx` | 修订号徽标与审批门禁面板 |
| `tests/engine.test.ts` | 核心语义单元测试（14 项） |

## 技术栈

Next.js App Router、Chakra UI、Zustand、TanStack Query、tRPC、Zod、TypeScript。

## 运行

```bash
npm install
npm run dev
```

```bash
npm test       # 纯函数核心单元测试（node:test）
npm run typecheck
npm run build
```

### 端到端手动验证（需先启动 dev）

```bash
scripts/e2e-check.sh
```

依次验证：迁移 → 字段级提交 → 写入失败 → 原号幂等重试 → 同窗口双改退回审阅且独占不覆盖 → 来源采纳重算 → 意见随排期变更失效 → 门禁更新 → 审批锁定 → 历史追溯。
